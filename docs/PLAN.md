# 개발 계획: 행사장 CCTV 실시간 혼잡도 웹

> 의뢰: 박람회(AI교육원) 웹사이트 느낌 그대로, 현장 CCTV 분석 결과를 **사람 수 + 여유/보통/혼잡 3단계**로 보여 주는 웹.
> 기준 명수는 현장을 보고 어드민에서 조정. 나중에 박람회 메인 웹에 연결.

## 1. 역할 나누기

| 구간 | 담당 | 내용 |
|---|---|---|
| CCTV → Redis | **YOBA (의뢰자)** | RTSP 수신, 사람 검출, 구역 집계, 블러, Redis에 최신 값 쓰기 |
| Redis → 브라우저 | **이 저장소 (웹)** | 스무딩, 3단계 판정, 장애 판정, 실시간 푸시, 영상 중계, 통계 DB, 어드민 |
| 박람회 메인 웹 연결 | 박람회 웹 담당 | iframe으로 넣거나 `/api/state` JSON을 받아 씀 (5장) |

둘 사이의 약속은 [REDIS_CONTRACT.md](REDIS_CONTRACT.md) 한 문서로 정리했습니다. **YOBA에서 할 일은 이 문서의 키 3개를 쓰는 것뿐**입니다.

## 2. 구조

```
CCTV 1대 (RTSP)
  └▶ YOBA 실시간 처리 (매 프레임: 검출 → 구역 집계 → 블러)
       └▶ Redis
            ├ yoba:live:{cam}   인원·fps·지연·블러 상태 JSON
            └ yoba:frame:{cam}  블러된 JPEG (TTL 5초)
                 └▶ 웹 서버 (Node.js)
                      ├ 0.2초마다 Redis 읽기 → 스무딩(약 2초) → 3단계 판정 → 3초 무갱신이면 "확인 불가"
                      ├ WebSocket: 0.5초마다 인원·단계·상태 푸시
                      ├ /snapshot/{cam}.jpg : 축소 화면용 최신 1장 (1초마다 갱신)
                      ├ /stream/{cam}.mjpg  : 확대 화면용 MJPEG (동시 시청 상한)
                      └ SQLite: 1초마다 인원 기록 → 시간대별 통계·CSV
```

### 결정한 것과 이유

| 결정 | 이유 |
|---|---|
| 단계 판정을 **웹 서버**에서 | 어드민이 사람 수 기준을 바꾸면 YOBA 재시작 없이 즉시 반영 |
| 장애 판정은 "값이 마지막으로 **바뀐** 시각"으로 | YOBA 노트북과 웹 서버 시계가 달라도 오판하지 않음 |
| 축소 화면은 1초 스냅샷, **MJPEG는 확대 화면에서만** | 박람회 때 3,000명+ 접속. 전원 MJPEG(장당 50KB × 8fps)면 서버 대역폭이 버티지 못함. 스냅샷은 nginx/CDN 캐시도 가능 |
| 구역 테두리·인원은 **브라우저가 그림** | YOBA는 블러 이미지만 보내면 됨. 색은 기준값이 바뀌어도 바로 반영 |
| 통계는 "평균 동시 인원" | YOBA는 사람을 추적하지 않아 누적 방문자 수를 만들 수 없음. 라벨에 명시 |
| 빌드 없는 HTML/CSS/JS + Node 하나 | 데모 사이트와 같은 방식이라 박람회 웹에 옮겨 붙이기 쉬움. 의존성 3개 (express, ws, ioredis), DB는 Node 내장 SQLite |

## 3. 화면

디자인은 데모 사이트(`ai.glink.kr/dev/s/dash/demo.html`)의 토큰을 그대로 가져왔습니다 (`public/css/tokens.css`). 파란 헤더, 노란 강조, 초록·주황·빨강 상태색, 어두운 CCTV 패널, 지도 SVG.

**방문객 화면 `/`**
- 지도: 데모 지도 그대로. AI교육원 링·배지 색이 현재 혼잡도를 따라감 (혼잡이면 깜빡임). 주차·교통은 데이터가 없어 회색(확인 중)
- 요약: 현재 화면 사람 N명 / 혼잡도 배지 / CCTV 1/1
- CCTV: 블러 영상 + 구역 테두리(단계 색) + 구역별 인원. 누르면 확대(MJPEG)
- 장애: 3초 넘게 갱신이 없으면 회색 "확인 불가" (서버가 판정 + 브라우저도 WebSocket이 끊기면 3초 뒤 스스로 회색 처리) → 꺼진 카메라가 "여유"로 보이지 않음
- 오늘 시간대별 평균 동시 인원 막대 그래프 (여유/혼잡 구간 표시)

**어드민 `/admin`** (비밀번호 로그인)
- 혼잡도 기준: "N명 이하 여유 / M명 이상 혼잡" 입력 → 눈금 막대에 현재 인원 위치 표시 → "현재 13명 기준이면 여유 → 보통" 미리보기 → 저장 즉시 반영 (단계가 바로 바뀌면 확인창)
- 구역별 기준 (선택)
- 처리 상태: 연결, 처리 fps, 지연, 마지막 프레임 수신 시각, 블러 검증 상태, 블러 실패(오늘/누적), 접속자 수
- 1시간 단위 통계: 평균 동시 인원, 최대 인원, 피크 시각, 정상 수신률, 블러 실패 (+그래프, 날짜 선택)
- CSV 내보내기 (시간별/분별, 엑셀 한글 깨짐 방지)
- 기준 변경 기록

## 4. 일정

| 단계 | 내용 | 상태 |
|---|---|---|
| 1. 웹 MVP | 공개 화면, 어드민, 데모 모드, 통계·CSV, 테스트 | **완료** (이 저장소) |
| 2. Redis 약속 확정 | YOBA에 `--live --publish` 구현됨 (spec 9.4, 실제 카메라·Redis 미검증). 웹은 `npm run check-redis`로 대조 | YOBA 반영됨 · 검증 남음 |
| 3. 연동 테스트 | 실제 Redis + 가짜 YOBA(`npm run fake-yoba`) → 실제 YOBA + 웹캠 → 현장 CCTV | 함께 |
| 4. 현장 기준값 | 현장에서 실제 인원 보며 어드민에서 N/M 조정 | 현장 |
| 5. 배포 | 서버 1대(Node + Redis + nginx), HTTPS, 비밀번호 설정 | README 참고 |
| 6. 박람회 웹 연결 | iframe 또는 `/api/state` | 박람회 웹 담당 |
| 7. 추가 기능 | 의뢰자가 "차차 말해줄" 기능 | 추후 |

### 연동 테스트 체크리스트
- [ ] `npm run fake-yoba`로 화면 숫자·테두리 색이 움직임
- [ ] `--stop-after`로 멈췄을 때 3초 안에 회색 "확인 불가" + CCTV 0/1
- [ ] YOBA를 다시 켜면 자동 복구
- [ ] Redis를 끄면 "확인 불가", 다시 켜면 자동 복구 (웹 서버 재시작 불필요)
- [ ] 블러 실패 시 검은 화면 + 어드민 블러 실패 횟수 증가
- [ ] 어드민 기준 저장 → 방문객 화면 즉시 반영
- [ ] 휴대폰에서 공개 화면 확인 (관람객 대부분이 휴대폰)
- [ ] 접속자 많을 때: 확대 영상 상한 도달 시 1초 스냅샷으로 자동 전환

## 5. 박람회 웹에 연결하는 방법

1. **iframe (가장 쉬움)**: `<iframe src="https://혼잡도서버/" ...>` — 디자인이 같아 자연스럽게 붙음
2. **JSON만 가져가기**: `GET /api/state` (인원·단계·CCTV 상태), `GET /api/hourly` (오늘 추이). 실시간이 필요하면 `wss://혼잡도서버/ws`. 박람회 지도 SVG의 `ai-congestion-ring`에 색만 칠하면 됨 (`public/js/public.js`의 `setMapLevel` 참고)

## 6. 정해야 할 것 (의뢰자에게 질문)

- [ ] CCTV는 1대 확정인지 (코드는 여러 대도 지원)
- [ ] 구역(ROI)을 나눌지, 화면 전체 1구역인지
- [ ] 초기 기준값 (기본: 20명 이하 여유 / 50명 이상 혼잡)
- [ ] 서버를 어디에 둘지 (YOBA 노트북과 같은 망인지, Redis 주소)
- [ ] 행사 이름·제목 문구 (지금은 "AI교육원 행사장 실시간 혼잡도")
- [ ] 통계 보관 기간 (지금은 계속 보관, 1일 약 17만 행 · 수십 MB 수준)
- [ ] 추가 기능 목록
